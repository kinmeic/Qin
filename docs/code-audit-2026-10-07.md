## 发现与修复

以下 9 类问题均已修复；P1 为安全风险，P2 为执行、交互或资源限制缺陷，P3 为显示正确性问题。

| 级别 | 问题 | 修复及证据 |
| --- | --- | --- |
| P1 | 脱敏跳过任何以 `[REDACTED]` 开头的秘密值，后缀可能原样泄露，例如 `password=[REDACTED]secret`。 | 仅当占位符构成完整值时才跳过；否则继续扫描并掩盖整个值。验证带引号、JSON、所有分片边界及重复脱敏稳定性。 |
| P1 | 非流式响应忽略 `finish_reason`，即使 `length`/`content_filter` 的响应包含有效工具参数，也会进入执行流程。 | 与流式解析共用完成原因校验，在返回工具调用前拒绝不完整响应；本地 HTTP 测试覆盖截断、过滤、未知原因和正常调用。兼容未提供该字段的服务。 |
| P2 | TUI 交接只继承 stdin，stdout/stderr 仍为管道且控制字符被过滤，编辑器和全屏程序无法获得真正的终端输出。Git 的 `-C`/`-c` 等全局参数还会掩盖需要交互的子命令。 | 交接后继承三个标准流；普通命令仍使用捕获路径。正确跳过 Git 全局参数。伪终端测试验证实际输入、三个终端文件描述符、ANSI 序列、退出码及恢复 TUI；分类回归覆盖带参数的 Git 操作。 |
| P2 | TUI 审批使用同步无限等待，外层异步时限不能中断该等待；超时后旧审批弹窗还会拦截输入。 | 等待时检查取消与本轮截止时间，收到答案后再次检查；本轮结束清除审批。验证无 UI 回答时的取消/超时，以及真实 TUI 中后续命令未执行、工具结果配对及退出。 |
| P2 | TUI 事件通道没有容量限制，且一次循环无限排空；持续输出可能积压内存或饿死键盘/重绘。 | 通道限制为 128 个事件并施加背压，每次 UI 循环最多处理 128 个事件。回归验证满队列拒绝额外即时发送、消费后恢复容量。 |
| P2 | 命令捕获结果在每个读取分片前插入 `stdout:`/`stderr:`，破坏同一输出流的文本、行和表格。 | 分别按顺序累积 stdout/stderr，共享输出字节预算；完成时每个非空流仅添加一次标签。验证多次间隔输出得到完整连续文本。跨流顺序不表示精确时间先后。 |
| P2 | 稀疏 Markdown 表格按最宽单元格给每行填充，少量输入即可扩展为大量输出；TUI 的事后裁剪无法防止该分配。 | 填充前估算扩展量；超过输入大小的 4 倍加 4096 字节时保留原始表格。验证宽单元格加大量短行不会产生放大。 |
| P3 | 超过显示上限的流式回答被裁剪后，与完整最终回答比较不相等，重复显示同一答案。 | 使用相同裁剪规则比较最终答案和已显示流式内容；验证仅保留一条截断答案。 |
| P3 | 已保存回答重新进入 TUI 后未进行表格对齐。 | 历史助手消息使用与新答案相同的表格处理；同时验证命令分片输出在活动消息插入后仍保持行间距。 |

## 行为边界

交互命令输出直接交给用户终端，因此不由 Qin 捕获、过滤或脱敏；模型取得退出状态和明确的直接展示提示。普通命令继续使用有界捕获、脱敏和 TUI 流式输出。审批时限修复针对 TUI 等待；CLI 的终端读取仍采用原有交互方式。

Shell/路径规则属于应用层防护，不是操作系统沙箱；前次审计记录的并发父目录替换、撤销元数据范围和单主机会话锁边界仍适用。本地伪终端与模拟服务无法证明所有终端、真实模型、远端认证和 OpenWrt 实机组合的行为。多平台发布构建由既有签名/校验和/SBOM/构建证明流程完成。
